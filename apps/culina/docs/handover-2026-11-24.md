## How the work was delegated

Each change: one implementing agent in a worktree of its own, then a
reviewing agent that wrote none of it and is given the task and the
staged diff, not the builder's conclusions; the builder fixes what the
review finds (the lead sends the findings to the same agent); where the
fixes touched data, a shared package or sentences shown to the cook,
the same reviewer looks a second time; the lead applies the staged
diff to the branch, commits, writes the entry in the root
`docs/reviews.md`, opens the pull request and merges when CI is green.
What worked:

- The builder stages (`git add -A`) and does not commit; a commit by a
  subagent was refused by the permission check, and committing is the
  lead's part anyway. The lead takes the work over with
  `git -C <worktree> diff --cached --binary | git apply --index`.
- A worktree may start behind the branch: the brief names the commit
  to stand on.
- The reviewer is told to use the thing (build the site, drive it in a
  browser as a cook would, compare each sentence with the store), not
  only to read the diff. Every defect a user would have seen on this
  day was found that way, none by the builder's own checks.
- Agents that run the browser tests run one after the other. Mixtura's
  e2e needs `MIXTURA_CHROMIUM` set; the others
  `PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium`.
- A pull request that changes an app's native package in import paths
  only fails the check "<app> / Changelog"; the label `no-changelog`
  is the documented way.

The briefs first used are kept in
[agent briefs](agent-briefs/impl-brief.md) (`impl-brief`,
`review-brief`, `writer-brief`, `reader-brief`); in them `<scratch>`
stands for the session's scratch folder. Implementers and reviewers ran
on the second-largest model, recipe writers and readers on the smaller
one.

For the catalogue the USDA data is needed in a scratch folder
([development](development.md#ingredient-catalogue)): the rebuild is
`node tools/catalogue/build.mjs <dir>/fdc-sr-legacy --refuse <dir>/fdc-sr28/FOOD_DES.txt`,
then `node tools/flavordb/link-build.mjs`.
`node tools/content/find-ingredient.mjs <word>` finds a catalogue row
by its English or German name.
