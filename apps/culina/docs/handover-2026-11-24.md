## How the work was delegated

Each change: one implementing agent, then a reviewing agent that wrote
none of it and is given the task and the diff, not the builder's
conclusions; the builder fixes what the review finds; the lead
commits, writes the entry in the root `docs/reviews.md` and merges
when CI is green. Agents that run the browser tests run one after the
other: two runs side by side make a navigation check time out. The
briefs used are kept in [agent briefs](agent-briefs/impl-brief.md)
(`impl-brief`, `review-brief`, `writer-brief`, `reader-brief`); in
them `<scratch>` stands for the session's scratch folder. The
implementers and reviewers ran on the second-largest model, recipe
writers and readers on the smaller one.

For the catalogue the USDA data is needed in a scratch folder
([development](development.md#ingredient-catalogue)): the rebuild is
`node tools/catalogue/build.mjs <dir>/fdc-sr-legacy --refuse <dir>/fdc-sr28/FOOD_DES.txt`,
then `node tools/flavordb/link-build.mjs`.
`node tools/content/find-ingredient.mjs <word>` finds a catalogue row
by its English or German name. Locally the browser tests need
`PLAYWRIGHT_CHROMIUM_PATH=/opt/pw-browsers/chromium`.
