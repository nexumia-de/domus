# Data model

The entities the engine, the store and import/export agree on. The
machine-readable form is the JSON Schemas in
[`packages/engine/schemas/`](../packages/engine/schemas/); a test fails
when a field of the tables below is missing in a schema or the other way
round, and when a "required" cell differs from the schema.

Principle: **derive, don't store** ([AGENTS.md](../AGENTS.md)). Only what
the user entered, and seed data, is stored; the last section lists what
is computed every time. The storage layout (IndexedDB) is in [store](store.md); the model here
is independent of it.

No bartending number is defined in this document. Where a figure needs
a source (usual ranges, dilution, yields) the field has no default; the
formulas are in [balance](balance.md) and the unit table in
[units](units.md).

## Units of measure, recorded once

| Quantity  | Stored as                 | Range    | Note                                                                    |
| --------- | ------------------------- | -------- | ----------------------------------------------------------------------- |
| ABV       | percent, `40` is 40 %     | 0 to 100 | Not a fraction. Same in every schema (`abvPercent` in `common`).        |
| Sugar     | grams per 100 ml          | 0 up     | Syrups can exceed 100 per 100 ml (`sugarGPer100Ml`).                    |
| Acid      | percent                   | 0 to 100 | The reference acid (for example citric equivalent) is fixed in balance. |
| Amount    | number plus unit id       | above 0  | Never a string like `"1 1/2 oz"`; the unit table is in units.           |
| Time span | whole days (`shelfLife…`) | 0 up     |                                                                         |
| Date      | `YYYY-MM-DD`              |          | Stock dates.                                                            |
| Instant   | ISO 8601 UTC with `Z`     |          | Supplied by the host; the engine has no clock.                          |

The schemas keep these in one place, `common.schema.json`, and every
schema refers to it.

## Ids

- **Seed ids** are lower-case slugs (`^[a-z0-9]+(-[a-z0-9]+)*$`, at most
  80 characters), human-readable and stable: `lemon-juice`, `daiquiri`.
  They come from the seed data ([seed data](seed-data.md)) and are never
  reused for another thing.
- **User ids** are `u-` plus a UUID in lower case (`u-3f1c2a52-8d1e-…`),
  generated by the host (the engine has no randomness), so two devices
  never collide and an import cannot overwrite a seed entity. A seed slug
  never starts with `u-` followed by a UUID.
- Both match the one `id` pattern in the schemas; the `u-` form is a rule
  of the store, not of the schema.
- **Renaming** changes `name` only. The id never changes; references stay
  valid. Seed entities are read-only: to change one, the user makes a new
  user ingredient with the seed one as `parentId`.
- **Deleted or missing targets.** A store refuses to delete a user entity
  that others reference. If a reference still points to nothing (a seed
  entity dropped in a later seed version, an import without its parts),
  nothing is deleted or repaired silently: the engine reports the line as
  unresolved and everything derived from it is marked incomplete. A seed
  version that drops an id keeps a `replacedBy` map in the seed data so a
  migration can rewrite references.

## Ingredient

A node of a tree with the levels `category`, `type`, `product`, joined by
`parentId` (absent on a root). A child's level is lower than its parent's
(category above type above product); there are no cycles; both are
checked by the engine, not by the schema.

| Field               | Stored or derived | Required | Meaning                                                                                                                                                                                                                                                                   |
| ------------------- | ----------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                | stored            | yes      | Id, see above.                                                                                                                                                                                                                                                            |
| `name`              | stored            | yes      | Display name.                                                                                                                                                                                                                                                             |
| `level`             | stored            | yes      | `category`, `type` or `product`.                                                                                                                                                                                                                                          |
| `parentId`          | stored            | no       | Id of the parent ingredient.                                                                                                                                                                                                                                              |
| `role`              | stored            | no       | `base`, `modifier`, `sweet`, `sour`, `bitter`, `accent`, `texture` or `lengthener`. Inherited.                                                                                                                                                                            |
| `abv`               | stored            | no       | ABV in percent. Inherited. Absent on a prepared ingredient.                                                                                                                                                                                                               |
| `sugar`             | stored            | no       | Sugar in g per 100 ml. Inherited. Absent on a prepared ingredient.                                                                                                                                                                                                        |
| `acid`              | stored            | no       | Acid in percent. Inherited. Absent on a prepared ingredient.                                                                                                                                                                                                              |
| `shelfLifeDays`     | stored            | no       | Whole days. Inherited.                                                                                                                                                                                                                                                    |
| `substitutionClass` | stored            | no       | Id of a class of ingredients that can stand in for each other by default. Inherited.                                                                                                                                                                                      |
| `cost`              | stored            | no       | Price paid for a quantity: `price`, `currency` (ISO 4217 code), `quantity` (amount and unit). Not inherited.                                                                                                                                                              |
| `cost.price`        | stored            | yes      | Price, 0 or more.                                                                                                                                                                                                                                                         |
| `cost.currency`     | stored            | yes      | ISO 4217 code, three capital letters.                                                                                                                                                                                                                                     |
| `cost.quantity`     | stored            | yes      | Quantity the price is for (amount and unit).                                                                                                                                                                                                                              |
| `unitVolumes`       | stored            | no       | Volume of one counted unit of this ingredient by unit id (`whole`, `slice`, `leaf`, ...): `{ ml, evidence, source? }`. `ml` above 0, `evidence` is `derived`, `secondary` or `assumption`. Not inherited; the engine never invents one ([units](units.md#counted-units)). |
| `prepared`          | stored            | no       | Present if the ingredient is made from a spec, see below.                                                                                                                                                                                                                 |
| `prepared.specId`   | stored            | yes      | The spec that makes it (its newest version is used).                                                                                                                                                                                                                      |
| `prepared.yield`    | stored            | yes      | Quantity one run of the spec yields (amount and unit).                                                                                                                                                                                                                    |
| `assumed`           | stored            | no       | Names of properties of this record that are assumptions, unverified. Shown to the user, never hidden.                                                                                                                                                                     |
| `source`            | stored            | no       | Where the figures come from, see Shared types.                                                                                                                                                                                                                            |
| `notes`             | stored            | no       | Free text.                                                                                                                                                                                                                                                                |
| `abvResolved`       | derived           | -        | `abv` after inheritance, or computed for a prepared ingredient. Likewise `sugar`, `acid`, `role`, `shelfLifeDays`, `substitutionClass`.                                                                                                                                   |

**Inheritance.** `role`, `abv`, `sugar`, `acid`, `shelfLifeDays` and
`substitutionClass` are read from the nearest ancestor (the ingredient
itself first) that has them; a child may override any of them. `id`,
`name`, `level`, `parentId` and `cost` are never inherited: a price
belongs to one bottle, and a category has no price. A property that no
ancestor has stays unknown; the engine never fills it with a default, and
anything that needs it is marked incomplete. A recipe that asks for a
parent ("citrus juice") is satisfied by any descendant in stock.

## Prepared ingredient

An ingredient with `prepared` set. Its spec lists the parts; ABV, sugar
and acid of the result are computed from them (volume weighted, see
[balance](balance.md)) and are therefore not stored: the schema rejects
`abv`, `sugar` and `acid` next to `prepared`. `prepared.yield` is what
one run makes, so scaling and batching can turn it into amounts of the
parts; `shelfLifeDays` is stored on the ingredient because it comes from
experience, not from the parts. Spec lines refer to a prepared
ingredient like to any other, by `ingredientId`. A prepared ingredient
must not (directly or through others) be part of its own spec; the engine
checks it.

Clarified with the engine ([ingredients](ingredients.md)): the computed
ABV, sugar and acid are never inherited from an ancestor of a prepared
ingredient; if a spec asks for it, `prepared.yield` is the volume of the
result (solid sugar dissolves into less than the sum of its parts), and
the totals of ethanol, sugar and acid are conserved.

## Template

A drink family: slots with a role and a ratio range, a method, usual
ranges of the finished drink.

| Field              | Stored or derived | Required | Meaning                                                                                                                                                          |
| ------------------ | ----------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`               | stored            | yes      | Id.                                                                                                                                                              |
| `name`             | stored            | yes      | Display name.                                                                                                                                                    |
| `parentId`         | stored            | no       | Template this one is a variant of (a sour whose sweet part is a liqueur).                                                                                        |
| `alcohol`          | stored            | no       | `none` or `low`: the template is a variant for drinks of that computed alcohol class and needs `parentId`; `matchSpec` offers it only when asked for that class. |
| `slots`            | stored            | yes      | At least one slot.                                                                                                                                               |
| `slots[].id`       | stored            | yes      | Id of the slot, unique within the template.                                                                                                                      |
| `slots[].role`     | stored            | yes      | Role the filling ingredient has.                                                                                                                                 |
| `slots[].minParts` | stored            | yes      | Lower end of the ratio in parts, above 0.                                                                                                                        |
| `slots[].maxParts` | stored            | yes      | Upper end, not below `minParts` (engine check).                                                                                                                  |
| `slots[].optional` | stored            | no       | `true` if the slot may stay empty; absent means required.                                                                                                        |
| `slots[].note`     | stored            | no       | Free text.                                                                                                                                                       |
| `slotEvidence`     | stored            | no       | `verified`, `secondary`, `derived` or `assumption`: how well the ratios are known.                                                                               |
| `method`           | stored            | yes      | Method id (for example shake or stir); dilution per method is in balance.                                                                                        |
| `glass`            | stored            | no       | Glass id.                                                                                                                                                        |
| `usual`            | stored            | no       | Usual ranges after dilution; needs `source`.                                                                                                                     |
| `usual.abv`        | stored            | no       | Range (`min`, `max`) in percent.                                                                                                                                 |
| `usual.sugar`      | stored            | no       | Range in g per 100 ml.                                                                                                                                           |
| `usual.acid`       | stored            | no       | Range in percent.                                                                                                                                                |
| `usual.evidence`   | stored            | no       | Same values as `slotEvidence`, for the three ranges.                                                                                                             |
| `source`           | stored            | no       | Source of the ranges.                                                                                                                                            |
| `notes`            | stored            | no       | Free text.                                                                                                                                                       |

Ratios are in parts, not in a unit, so a template works in ounces and in
millilitres. The first slot with role `base` is the reference: its volume
counts as the parts of its own `minParts`/`maxParts` (2 in the root
templates, the "2 oz" of the practice), and every other slot is
measured against it ([templates](templates.md#matching)). The ranges have no default;
a template without a verified range has no `usual` and shows no verdict.

## Spec

One version of a drink. Versions of one drink share `lineageId`; each
version is its own record, so older ones stay readable. `version` counts
from 1 inside a lineage. `parentId` is the spec this one was made from:
for the first version of a riff, the spec it riffs on; for a later
version, the previous version.

| Field                                | Stored or derived | Required | Meaning                                                                                                                   |
| ------------------------------------ | ----------------- | -------- | ------------------------------------------------------------------------------------------------------------------------- |
| `id`                                 | stored            | yes      | Id of this version.                                                                                                       |
| `lineageId`                          | stored            | yes      | Id shared by all versions of one drink; the first version uses its own id.                                                |
| `version`                            | stored            | yes      | Integer from 1.                                                                                                           |
| `parentId`                           | stored            | no       | Spec this version was made from.                                                                                          |
| `name`                               | stored            | yes      | Display name.                                                                                                             |
| `templateId`                         | stored            | no       | Template the drink follows.                                                                                               |
| `lines`                              | stored            | yes      | At least one line, in order.                                                                                              |
| `lines[].ingredientId`               | stored            | yes      | Ingredient or prepared ingredient.                                                                                        |
| `lines[].amount`                     | stored            | yes      | Amount above 0 in `unit`.                                                                                                 |
| `lines[].amountMax`                  | stored            | no       | Upper end if the line is a range.                                                                                         |
| `lines[].unit`                       | stored            | yes      | Unit id, see units; a counted unit (`whole`, `slice`, `leaf`, ...) or `top` is an amount without a volume of its own.     |
| `lines[].topMl`                      | stored            | no       | Volume in ml of a line whose `unit` is `top`; balance counts the line only when it is given. Only valid with `unit: top`. |
| `lines[].role`                       | stored            | no       | Role in this drink; absent means the ingredient's resolved role.                                                          |
| `lines[].optional`                   | stored            | no       | `true` if the drink works without it.                                                                                     |
| `lines[].note`                       | stored            | no       | Free text, for example "preferably …".                                                                                    |
| `lines[].substitutes`                | stored            | no       | Ingredients that can stand in for this line.                                                                              |
| `lines[].substitutes[].ingredientId` | stored            | yes      | The substitute.                                                                                                           |
| `lines[].substitutes[].amount`       | stored            | no       | Own amount if it differs; then `unit` is required.                                                                        |
| `lines[].substitutes[].unit`         | stored            | no       | Unit of that amount.                                                                                                      |
| `method`                             | stored            | no       | Method id.                                                                                                                |
| `glass`                              | stored            | no       | Glass id.                                                                                                                 |
| `garnish`                            | stored            | no       | Free text.                                                                                                                |
| `notes`                              | stored            | no       | Free text.                                                                                                                |
| `tags`                               | stored            | no       | Short keywords, unique.                                                                                                   |
| `status`                             | stored            | yes      | `draft`, `on-menu` or `retired`.                                                                                          |
| `source`                             | stored            | no       | Where a seed spec comes from, see Shared types.                                                                           |
| `createdAt`                          | stored            | no       | Instant, supplied by the host.                                                                                            |
| `updatedAt`                          | stored            | no       | Instant, supplied by the host.                                                                                            |
| `balance`                            | derived           | -        | ABV, sugar, acid, volume and ratios after dilution; see balance.                                                          |
| `cost`                               | derived           | -        | Sum of amounts times cost of the lines' ingredients.                                                                      |

**Optional lines and what the stock allows.** A line with
`optional: true` never blocks "makeable": a spec is makeable when every
other line is satisfied by the stock (the ingredient, a descendant, a
prepared ingredient whose parts are all there, and with substitutes allowed
the line's `substitutes` or a same-class, same-role ingredient). The free-text
`garnish` is never read. Rules and result shapes: [makeable](makeable.md).

A spec whose lines resolve to ingredients with known properties gets
balance figures; a spec that is the recipe of a prepared ingredient is an
ordinary spec.

## Stock

One record per ingredient the user keeps track of; no record means "not
tracked", `present: false` means "known to be out".

| Field          | Stored or derived | Required | Meaning                                     |
| -------------- | ----------------- | -------- | ------------------------------------------- |
| `ingredientId` | stored            | yes      | The ingredient; also the key of the record. |
| `present`      | stored            | yes      | At hand or not.                             |
| `openedOn`     | stored            | no       | Date the bottle or batch was opened.        |
| `bestBefore`   | stored            | no       | Date after which it should not be used.     |
| `note`         | stored            | no       | Free text.                                  |

Stock has no quantity: an ingredient is at hand or not, and what the stock
allows ([makeable](makeable.md)) is decided on that alone. `bestBefore` is
information for the app; the engine has no clock and does not read it.

**Marking a node.** A record for a type or category means "some of it": it satisfies a line that names it or any ancestor, not a line that names a product below it ([makeable](makeable.md#rules)). A record for a product satisfies that product and its ancestors. The Stock screen writes `present: true` on a mark and `present: false` on a second tap ([stock screen](screens-stock-settings.md#as-built-30-33)).

## Affinity

Two ingredients that go together, as inspiration. A source is required;
an affinity without one is not stored.

| Field         | Stored or derived | Required | Meaning                                                                                                                                                     |
| ------------- | ----------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`          | stored            | yes      | Id.                                                                                                                                                         |
| `ingredients` | stored            | yes      | Exactly two different ingredient ids; the pair is unordered.                                                                                                |
| `strength`    | stored            | yes      | 1, 2 or 3 (usable, good, classic). A Mixtura scale, an assumption; the converter maps each source's own tiers to it and notes the mapping in `source.note`. |
| `kind`        | stored            | yes      | `classic`, `complement`, `contrast` or `shared-aroma`.                                                                                                      |
| `source`      | stored            | yes      | Where the pair comes from.                                                                                                                                  |
| `notes`       | stored            | no       | Free text.                                                                                                                                                  |

## Stored versus derived

| Value                                              | Stored | Derived from                                                  |
| -------------------------------------------------- | ------ | ------------------------------------------------------------- |
| Ingredient properties after inheritance            | no     | The ingredient and its ancestors.                             |
| Properties of a prepared ingredient                | no     | Its spec's lines.                                             |
| Balance figures (ABV, sugar, acid, volume, ratios) | no     | Lines, ingredient properties, method ([balance](balance.md)). |
| Distance of a spec from its template's usual range | no     | Balance figures and the template.                             |
| Cost per drink and per batch                       | no     | Lines, `cost` of ingredients, units.                          |
| Makeable now, with substitutes                     | no     | Specs, stock, ingredient tree, substitutes.                   |
| Unlock ranking (which bottle makes the most)       | no     | Specs, stock.                                                 |
| Newest version of a lineage                        | no     | `lineageId` and `version`.                                    |
| Amounts in another unit, scaled or batched amounts | no     | Lines and the unit table ([units](units.md)).                 |
| Stored: everything in the entity tables above      | yes    | Entered by the user or taken from seed data.                  |

## Export file

One JSON file with everything the user entered; seed data is not in it
([PWA decision](decisions/pwa-own-data.md)). Schema:
`export.schema.json`.

| Field           | Stored or derived | Required | Meaning                                                              |
| --------------- | ----------------- | -------- | -------------------------------------------------------------------- |
| `app`           | stored            | yes      | Always `mixtura`, so another app's file is refused.                  |
| `formatVersion` | stored            | yes      | Integer, starts at 1.                                                |
| `exportedAt`    | stored            | yes      | Instant supplied by the host.                                        |
| `seedVersion`   | stored            | no       | Version or commit of the seed data the references were made against. |
| `ingredients`   | stored            | yes      | User ingredients, prepared ones included.                            |
| `templates`     | stored            | yes      | User templates.                                                      |
| `specs`         | stored            | yes      | User specs, all versions.                                            |
| `stock`         | stored            | yes      | Stock records.                                                       |
| `affinities`    | stored            | yes      | User affinities.                                                     |

**Migration rule.** Each change of the format that removes, renames or
re-interprets a field raises `formatVersion` by one and comes with a pure
function from version n to n+1 and a test vector. Adding an optional field
does not. The reader applies the functions in order until the current
version and validates the result against the current schema. A file with a
higher version than the app knows is refused with a message that names
both versions; a file is never partly imported, and no field is dropped
silently. `export.schema.json` always describes the current version only
(`formatVersion` is a constant there); older versions live in the
migration code and its vectors.

**Version history.** Version 1 is the first format; no migration exists yet.
The optional fields `lines[].topMl` and `unitVolumes` and the counted unit
ids (`whole`, `slice`, ...) were added to version 1 without a bump: an older
file has none of them and stays valid.
Reading, limits and merge rules: [export format](export-format.md).

## Storage

On the device the entities live in IndexedDB, schema version 2: stores
`specs` (one record per version, indexed by `lineageId`),
`ingredients` (prepared ones included), `templates`, `affinities`,
`stock` (keyed by `ingredientId`), `settings` and `meta`. Seed data is
not stored there. Stores, indexes, migrations: [store](store.md).

## Schemas and examples

`packages/engine/schemas/`: `common`, `ingredient`, `prepared-ingredient`,
`template`, `spec`, `stock`, `affinity`, `export` (`*.schema.json`, draft
2020-12, `additionalProperties: false` everywhere). `examples/valid/` and
`examples/invalid/` hold files named after their schema; the tests in
`packages/engine/test/` validate each valid file, require each invalid
one to fail with a named message, and compare this document with the
schemas. Validator: Ajv, a development dependency only
([dependencies](dependencies.md)); the schemas are not shipped in the
engine.
